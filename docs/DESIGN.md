# MoneyTrack Design

The visual system is generated by `ui-ux-pro-max` and stored in
[`design-system/moneytrack/MASTER.md`](../design-system/moneytrack/MASTER.md).
This document explains how the tokens are applied in the product.

---

## 1. Direction

**Dark, calm, data-first.** The dashboard is meant to be read at a glance at
night, on a laptop or a phone. Deep navy canvas, a single green accent for
positive/primary actions, red reserved for waste, amber for projections.

References that informed the layout: money-manager dashboards on Behance and
Dribbble — KPI strip, one large trend chart, a category donut, and a compact
activity list, with navigation pushed to a persistent rail.

**Anti-patterns we avoid:** light-mode default, emoji as icons, layout-shifting
hover transforms, low-contrast grey text, invisible focus rings.

---

## 2. Tokens

Defined as CSS custom properties in `src/index.css` via Tailwind v4 `@theme`.

| Token | Value | Use |
|---|---|---|
| `--color-canvas` | `#020617` | App background |
| `--color-surface` | `#0e1223` | Cards, sidebar |
| `--color-surface-2` | `#131a2c` | Inputs, chips, icon tiles |
| `--color-line` | `#1e293b` | Hairlines, card borders |
| `--color-line-strong` | `#334155` | Hover borders, table rules |
| `--color-ink` | `#f8fafc` | Primary text |
| `--color-muted` | `#94a3b8` | Secondary text |
| `--color-faint` | `#64748b` | Labels, metadata |
| `--color-accent` | `#22c55e` | Primary action, positive values |
| `--color-danger` | `#ef4444` | Waste, destructive |
| `--color-warn` | `#fbbf24` | Annual projections |
| `--color-info` | `#38bdf8` | Informational accents |

Category colours (`src/lib/format.js`): Groceries `#22c55e`, Dining `#fb7185`,
Subscriptions `#a78bfa`, Transport `#38bdf8`, Utilities `#fbbf24`,
Housing `#2dd4bf`, Fees `#f97316`, General `#94a3b8`. Every chart legend also
prints the label and value, so colour is never the only signal.

### Typography

- Headings and body: **Fira Sans** (300–700), base 16px, line-height 1.5.
- Numerals, dates, IDs: **Fira Code** with `tabular-nums` (`.num` utility) so
  figures do not jitter between renders.
- Micro-labels: 10–11px uppercase with wide tracking; body never below 12px.

### Spacing & shape

Dense dashboard scale: 4/8/12/16/24/32px. Cards use 16px radius, inputs and
buttons 12px, pills 999px. Elevation is a soft shadow plus a 1px border rather
than a glow, except the accent CTA which gets a subtle green halo.

## 3. Layout

```
┌────────────┬──────────────────────────────────────────────┐
│ Sidebar    │ Sticky top bar: page title · period · status  │
│ 248px      ├──────────────────────────────────────────────┤
│ Overview   │ KPI · KPI · KPI · KPI                        │
│ Transactions│ ┌──────────── trend (3/5) ┬ donut (2/5) ───┐ │
│ Import     │ └─────────────────────────┴─────────────────┘ │
│ Settings   │ ┌──── top waste (2/5) ┬ recent (3/5) ────────┐ │
│            │ └─────────────────────┴─────────────────────┘ │
│ user card  │ max-width 1152px, 16–32px gutters            │
└────────────┴──────────────────────────────────────────────┘
```

- **≥1024px** — fixed sidebar, content offset by 248px.
- **<1024px** — sidebar disappears; a 4-item bottom navigation (56px tall,
  `env(safe-area-inset-bottom)`) takes over. Exactly four destinations, so it
  stays within the five-item mobile limit.
- **<640px** — KPI grid collapses to two columns, tables become stacked cards,
  filters wrap, charts keep a 256px height.

Breakpoints tested: 375, 768, 1024, 1440.

## 4. Screens

| Screen | Job | Key components |
|---|---|---|
| Auth | Register or sign in, explain the product | Split brand panel + form, password reveal, demo shortcut |
| Overview | Answer "where did my money go?" | 4 KPIs, daily area chart, category donut, top waste bars, recent list |
| Transactions | Audit and export | Search, category select, waste toggle, responsive table/cards, CSV export |
| Import | Get data in | Dropzone, sample CSV, parsing explainer, result panel |
| Settings | Trust and control | Account, runtime status, backup/Postgres notes, demo reset, sign out |

### Navigation behaviour

- The active view is mirrored in `location.hash` (`#overview`,
  `#transactions`, …), so the browser back button and deep links work.
- `aria-current="page"` marks the active destination on both navigations.
- Sign out clears all cached summaries before returning to the auth screen.

## 5. Components

| Pattern | Rules |
|---|---|
| `Card` | `bg-surface`, 1px `line`, radius 16, soft shadow; optional hover lift via border/shadow only (no scale, no layout shift) |
| `Button` | Min height 36 (sm) / 44 (md/lg), 200ms colour transition, disabled at 50%, spinner replaces content area when loading |
| `Badge` | 11px, pill, tone-coded (neutral/accent/danger/warn/info) with text, never colour-only |
| `Input` | 40–44px tall, visible label above, 1px border → accent on focus |
| `EmptyState` | Icon tile + one-line cause + a single action |
| Chart tooltip | Dark glass panel, colour dot + label + monospace value |

## 6. Data visualisation

| Question | Chart | Why |
|---|---|---|
| How is spend trending? | Area chart, single series | Rhythm over 90 days; gradient fill keeps it quiet |
| What share per category? | Donut + legend list | Part-to-whole with ≤8 categories |
| Which merchants leak most? | Horizontal bars | Ranking, sorted, labelled with amounts |
| Headline numbers | KPI cards | Four max per row; each has a unit or comparison line |

Tooltips repeat the category name and value; axes are formatted compactly
(`$1.2K`). Charts declare `role="img"` with descriptive labels, and the same
numbers appear as text in legends and lists.

---

## 7. Motion

- Only two motions: 200ms colour/border transitions on interactive elements,
  and the loading spinner.
- `prefers-reduced-motion: reduce` collapses all durations to 0.01ms.
- No entrance animation on data tables (overshoot reads as sloppy in
  informational UI, per the design-system notes).

---

## 8. Accessibility checklist

- Stone/navy text pairs stay ≥ 7:1 (`#f8fafc` on `#020617`), muted labels ≥ 4.5:1.
- `:focus-visible` outline is always green, 2px, offset 2px.
- Icon-only controls (sign out, password reveal) have `aria-label`; decorative
  icons are `aria-hidden`.
- Form fields use real `<label for>`; errors appear adjacent to the form and use
  `role="alert"`.
- Bottom nav and sidebar are `<nav aria-label="Primary">` with 56px touch targets.
- No horizontal scrolling at 375px; long merchant names truncate with ellipsis.

## 9. Extending to mobile

The future React Native/Expo client should reuse:

- The API contracts in `docs/API.md` (stateless JSON + `x-user-id`).
- The token values above (map to a theme object).
- The same information hierarchy: KPI strip → trend → category split → activity.
- Four-tab bottom navigation. The web shell already behaves that way under
  1024px, which is the acceptance target for parity.

Swap the area chart for a native chart library, keep the same categories and
colour mapping so screenshots and habits carry over.
